# Dicionários

Depois de listas, tuplas e sets, você chega a uma estrutura que muda a forma como o programa representa informações reais: o <Glossario termo="dicionário" definition="Estrutura que guarda dados em pares chave-valor, permitindo acesso por nome da chave." />. Em vez de guardar uma sequência de itens, o dicionário guarda um “nome” e um “valor” juntos. Isso é muito parecido com um cadastro, um registro de clientes, um relatório de estoque ou até uma resposta de API da web.

Quando você abre um cadastro, normalmente pensa em termos de campos como nome, idade, cidade e e-mail. Em Python, isso costuma ser representado como um dicionário. Cada campo vira uma chave e cada informação vira um valor. Isso torna o código mais legível e muito mais natural para dados estruturados.

  - Quando usar dicionário em vez de lista, tupla ou set.

## 1. O que é um dicionário?

Um dicionário é uma coleção de pares chave-valor. A chave funciona como identificador, e o valor é a informação associada. Em muitos casos, você usa strings como chave: "nome", "idade", "curso". Mas também pode usar números ou tuplas, desde que a chave seja imutável.

A sintaxe é bem simples: você coloca as chaves entre chaves `{}` e separa cada par com `:`.

<CodeBlock title="dicionario_basico.py" code={`aluno = {"nome": "Ana", "idade": 29, "ativo": True}
print(aluno["nome"])
print(aluno["idade"])
aluno["curso"] = "Python"
print(aluno)
print(aluno.get("email", "sem e-mail"))`} />

```text
Ana
29
{'nome': 'Ana', 'idade': 29, 'ativo': True, 'curso': 'Python'}
sem e-mail
```

Esse exemplo mostra dois pontos centrais. Primeiro, o acesso por chave é direto e legível: `aluno["nome"]`. Segundo, `get` é uma forma segura de tentar acessar uma chave que pode não existir. Quando a chave não está presente, o dicionário devolve um valor padrão que você define, em vez de quebrar o programa com `KeyError`.

O dicionário também é uma estrutura muito boa para modelar informações heterogêneas. Você pode ter strings, números, listas e booleanos dentro do mesmo objeto, sem perder organização.

## 2. Inserindo, atualizando e removendo dados

Um dicionário não é estático. Ele cresce e se reorganiza conforme você precisa. Você pode inserir novas chaves, alterar valores existentes e remover itens quando não forem mais úteis.

<CodeBlock title="dicionario_operacoes.py" code={`estoque = {"pão": 4, "leite": 3}
estoque["café"] = 2
estoque["leite"] = 5
print(estoque)

estoque.setdefault("arroz", 6)
print(estoque.get("arroz"))

estoque.pop("café")
print(estoque)

estoque.update({"pão": 7, "ovos": 10})
print(estoque)`} />

```text
{'pão': 4, 'leite': 5, 'café': 2}
6
{'pão': 4, 'leite': 5, 'arroz': 6}
{'pão': 7, 'leite': 5, 'arroz': 6, 'ovos': 10}
```

Aqui aparece a lógica principal da mutabilidade do dicionário. `"café"` foi inserido, `"leite"` foi atualizado, `setdefault` evitou duplicação de chave e `pop` removeu um valor. `update` é especialmente útil quando você quer combinar dois dicionários ou aplicar novas informações em um registro já existente.

<Playground title="Experimento: montar um cadastro" code={`cadastro = {"nome": "Bruno", "idade": 21}
cadastro["cidade"] = "São Paulo"
cadastro["idade"] = 22
print(cadastro)
print(cadastro.get("telefone", "não informado"))`} />

Esse experimento ilustra uma situação muito comum: editar um registro em andamento. O dicionário facilita essa operação porque você trabalha com chaves nomeadas, e não com índices numéricos que mudam de contexto.

## 3. Percorrendo um dicionário

Uma das partes mais importantes do dicionário é a análise de seus itens. Você pode percorrer chaves, valores ou pares completos. Essa é a base para filtros, relatórios, contagem de frequência e transformação de dados.

<CodeBlock title="percorrer_dicionario.py" code={`pedido = {"cliente": "Helena", "total": 128.50, "status": "pago"}
print("Chaves:", list(pedido.keys()))
print("Valores:", list(pedido.values()))
print("Itens:")
for chave, valor in pedido.items():
    print(f"{chave}: {valor}")
print("cliente" in pedido)`} />

```text
Chaves: ['cliente', 'total', 'status']
Valores: ['Helena', 128.5, 'pago']
Itens:
cliente: Helena
total: 128.5
status: pago
True
```

Você vai notar que `items()` entrega pares de chave e valor em conjunto. Isso é muito útil quando você quer imprimir dados, validar regras ou mudar um registro do tipo “para cada campo, faça alguma ação”.

O uso de `in` também é importante: ele responde a pergunta “a chave existe?” sem precisar de `try/except` no caso mais simples. Isso deixa o código mais claro e seguro.

## 4. Frequência, agrupamento e dicionários aninhados

Dicionários são extremamente úteis para contar ocorrências. Quando você quer descobrir quantas vezes uma palavra aparece em um texto, o padrão é simples: para cada item, incremente o valor da chave correspondente.

<CodeBlock title="contagem_frequencia.py" code={`frases = "a b a c b a".split()
freq = {}
for palavra in frases:
    freq[palavra] = freq.get(palavra, 0) + 1
print(freq)

from collections import defaultdict
vetor = ["A", "B", "A", "C", "B", "A"]
agrupado = defaultdict(int)
for valor in vetor:
    agrupado[valor] += 1
print(dict(agrupado))`} />

```text
{'a': 3, 'b': 2, 'c': 1}
{'A': 3, 'B': 2, 'C': 1}
```

A primeira parte do código mostra o padrão clássico de contagem com `get()`. A segunda parte usa `defaultdict`, um tipo de dicionário que cria automaticamente a chave quando ela ainda não existe. Isso é muito útil em contagem e agrupamento de dados, como “quantos produtos por categoria?”, “quantas vendas por vendedor?” ou “quantos pedidos por cliente?”.

A estrutura mais importante do tópico 09, no entanto, é o dicionário aninhado. Em muitas APIs e arquivos JSON, você encontra dados dentro de dados. Por exemplo, um pedido pode ter cliente, itens e endereço. Cada item, por sua vez, pode ser um dicionário, e a lista de itens só existe dentro do pedido.

<CodeBlock title="api_like_response.py" code={`resposta = {
    "status": "ok",
    "dados": {
        "cliente": {
            "nome": "Maria",
            "cidade": "Recife"
        },
        "itens": [
            {"produto": "mouse", "quantidade": 2, "preco": 35.0},
            {"produto": "teclado", "quantidade": 1, "preco": 120.0}
        ]
    }
}

cliente = resposta["dados"]["cliente"]["nome"]
print(cliente)
print(resposta["dados"]["itens"][0]["produto"])
print(resposta["dados"]["itens"][1]["preco"])`} />

```text
Maria
mouse
120.0
```

Essa estrutura é muito comum em respostas de API: um dicionário em nível superior, outro dicionário dentro de `dados`, uma lista de itens e, dentro dela, dicionários menores. Isso explica por que dicionários são tão importantes em Python: eles modelam o formato natural de dados retornados por serviços web, arquivos JSON e sistemas de cadastro.

<Playground title="Experimento: extrair dados de um payload" code={`payload = {
    "empresa": "Codetrilha",
    "curso": "Python",
    "turma": {
        "alunos": [
            {"nome": "Iza", "nota": 9.5},
            {"nome": "Luca", "nota": 8.0},
            {"nome": "Nina", "nota": 10.0}
        ]
    }
}

for aluno in payload["turma"]["alunos"]:
    print(aluno["nome"], aluno["nota"])`} />

A leitura de estruturas aninhadas exige organização mental: você percorre camadas da estrutura em ordem. Primeiro, acessa o dicionário principal; depois, um subdicionário; depois, uma lista; e por fim, um dicionário dentro da lista. Esse padrão aparece em praticamente qualquer sistema real que trabalha com JSON ou com dados vindos de serviços externos.

## 5. Quando usar dicionário e como escolher a estrutura certa

A escolha da estrutura depende da pergunta que você quer responder. Lista serve quando você precisa de ordem e repetição; tupla serve quando a sequência é fixa; set serve para unicidade; dicionário serve quando a informação precisa ser referenciada por nome.

## 6. Armadilhas comuns

Mesmo com uma estrutura muito útil, alguns erros aparecem com frequência.

<Callout type="erro-comum" title="KeyError: chave inexistente">
  Quando você acessa uma chave que não foi criada, o Python lança `KeyError`. Isso costuma acontecer quando o nome da chave está digitado errado ou quando a estrutura ainda não foi preenchida.

  <CodeBlock title="keyerror_dicionario.py" code={`dados = {"nome": "Ana"}
print(dados["idade"])`} />

  ```text
  Traceback (most recent call last):
    File "<stdin>", line 2, in <module>
      print(dados["idade"])
  KeyError: 'idade'
  ```

  A correção é acessar com `get()` quando a presença da chave pode variar, ou verificar com `in` antes de usar o valor.
</Callout>

<Callout type="erro-comum" title="Alterar dicionário enquanto percorre">
  Se você tenta remover ou alterar um item enquanto itera sobre o dicionário, o comportamento pode quebrar ou gerar erro em algumas situações. Isso é especialmente comum quando você tenta apagar elementos combinando `for` e `pop`.

  <CodeBlock title="dicionario_while_iterating.py" code={`alunos = {"Ana": 9, "Bruno": 8, "Carla": 10}
for nome in alunos:
    if alunos[nome] < 9:
        del alunos[nome]
print(alunos)`} />

  ```text
  {'Ana': 9, 'Carla': 10}
  ```

  Em geral, a forma segura é percorrer uma cópia: `for nome, nota in list(alunos.items())` ou primeiro construir uma lista de chaves para alterar depois.
</Callout>

<Callout type="erro-comum" title="Usar lista como chave">
  Chaves em dicionários precisam ser imutáveis, porque o Python precisa calcular um identificador interno para elas. Uma lista não é hashable, então ela não pode ser usada como chave.

  <CodeBlock title="lista_como_chave.py" code={`perfil = {['nome', 'idade']: 'Ana'}`} />

  ```text
  Traceback (most recent call last):
    File "<stdin>", line 1, in <module>
      perfil = {['nome', 'idade']: 'Ana'}
  TypeError: unhashable type: 'list'
  ```

  Se você quer uma estrutura de chave composta, use uma tupla: `('Ana', 29)`, ou então use um dicionário interno mais semântico.
</Callout>

### No mercado de trabalho

Dicionários são a base de quase todo dado estruturado no mundo real. Em engenharia de software, eles aparecem em APIs, serviços web, arquivos JSON, autenticação, cadastros, integração entre sistemas e análise de dados. Quando você trabalha com sistemas que trocam informações entre front-end, back-end e banco de dados, o dicionário é a forma mais natural de representar a resposta recebida.

Em um contexto de dados, dicionários são usados para traduzir linhas de CSV, fazer agrupamentos, contar frequências e preparar dados para relatórios. Em automatizações, eles organizam configurações, parâmetros e resultados de processo. Isso faz do dicionário uma estrutura essencial para qualquer pessoa que queira construir aplicações reais, não apenas scripts simples.
