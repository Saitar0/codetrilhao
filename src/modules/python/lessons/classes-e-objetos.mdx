# Classes e objetos

Você já viu que Python lida muito bem com dados simples, listas e dicionários. Mas quando a lógica cresce, uma estrutura mais rica aparece: a classe. Ela reúne dados e comportamentos em uma única ideia. Em vez de pensar em “uma pessoa como nome e idade” em variáveis separadas, você passa a criar uma entidade chamada `Pessoa`, com os atributos dela e os métodos que descrevem o que ela pode fazer.

Esse movimento é o coração da orientação a objetos: modelar entidades do mundo real como objetos com identidade, estado e comportamento. Quando você cria uma classe, está definindo um molde; quando instancia, está criando um objeto concreto a partir desse molde.

<Callout type="importante" title="O que você vai aprender">
  - Como uma classe serve como molde para objetos.
  - Como `__init__` define o estado inicial de cada objeto.
  - Como usar `self` para acessar atributos e métodos do objeto atual.
  - Como separar responsabilidade em métodos claros e reutilizáveis.
</Callout>

## Classe, objeto e instância

Uma classe é uma descrição de um tipo de coisa. Um objeto é uma ocorrência real dessa classe. Em Python, você define uma classe com a palavra-chave `class` e cria uma instância chamando a classe como se fosse uma função.

A ideia central é simples: a classe explica o que a entidade “é”, enquanto o objeto guarda os dados concretos daquele caso.

<CodeBlock title="pessoa.py" code={`class Pessoa:
    def __init__(self, nome, idade):
        self.nome = nome
        self.idade = idade

    def apresentar(self):
        return f"{self.nome} tem {self.idade} anos"

ana = Pessoa("Ana", 22)
print(ana.nome)
print(ana.apresentar())
`} />

Saída:

```text
Ana
Ana tem 22 anos
```

A primeira linha cria a classe `Pessoa`. O `__init__` é chamado automaticamente quando você instancia a classe: `ana = Pessoa("Ana", 22)`. Dentro dele, `self` representa exatamente esse objeto recém-criado. O `self.nome` e `self.idade` são atributos de instância, ou seja, pertencem a cada objeto individual.

## Atributos de instância e de classe

Nem todo dado pertence a um objeto específico. Alguns valores são compartilhados por todas as instâncias. Por isso, Python diferencia entre atributos de instância e atributos de classe.

Um atributo de instância depende do objeto. Já um atributo de classe é compartilhado por todos os objetos dessa classe.

<CodeBlock title="produto.py" code={`class Produto:
    categoria = "eletrônicos"

    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco

p1 = Produto("Teclado", 180)
p2 = Produto("Mouse", 80)

print(Produto.categoria)
print(p1.categoria)
print(p2.preco)
`} />

Saída:

```text
eletrônicos
Eletrônicos
80
```

Esse exemplo mostra que `categoria` é parte da classe em si, e não de um objeto específico. Você pode acessar por `Produto.categoria` ou por `p1.categoria`. Já `preco` é um atributo de instância, porque cada produto pode ter um preço diferente.

<CodeBlock title="estado_por_objeto.py" code={`class Carrinho:
    def __init__(self):
        self.itens = []

    def adicionar(self, item):
        self.itens.append(item)

    def total(self):
        return len(self.itens)

c1 = Carrinho()
c2 = Carrinho()
c1.adicionar("banana")
c1.adicionar("maçã")
print(c1.total())
print(c2.total())
`} />

## Métodos e responsabilidade única

Muitos programas começam com funções simples, mas com o tempo surge a necessidade de agrupar regras relacionadas ao mesmo conceito. Em vez de espalhar a lógica em diversas funções, você coloca métodos dentro da classe.

Uma regra útil é pensar “cada classe deve ter uma responsabilidade clara”. Por exemplo, a classe `Pessoa` pode identificar a pessoa e apresentar a si mesma; a classe `Banco` pode cuidar de operações de conta; a classe `Pedido` pode calcular total e itens.

<CodeBlock title="conta_bancaria.py" code={`class ContaBancaria:
    def __init__(self, titular, saldo=0):
        self.titular = titular
        self._saldo = saldo

    def depositar(self, valor):
        if valor <= 0:
            raise ValueError("Valor deve ser positivo")
        self._saldo += valor

    def saldo(self):
        return self._saldo

    def __str__(self):
        return f"{self.titular}: R$ {self._saldo:.2f}"

conta = ContaBancaria("Ana", 150)
conta.depositar(50)
print(conta.saldo())
print(conta)
`} />

Saída:

```text
200
Ana: R$ 200.00
```

Esse exemplo é importante porque ele já mostra a base da ideia de orientação a objetos: dados e operações em um mesmo bloco. Em seguida, a aula vai aprofundar como proteger esse estado e como dar representação mais clara ao objeto.

## Quando uma classe faz sentido?

Você não precisa transformar tudo em classe. A regra é: use classes quando o problema tem entidades com identidade e regras próprias. Se você só quer armazenar dados temporários em um dicionário, talvez uma função resolva melhor. Se você quer representar uma conta bancária, um pedido, uma pessoa, um produto ou um funcionário, classes são muito úteis.

Uma classe melhora a clareza porque ela deixa explícito o que o objeto sabe e o que ele consegue fazer.

<Callout type="erro-comum" title="Método chamado na classe em vez do objeto">
  ```python
  class Pessoa:
      def apresentar(self):
          return "Olá!"

  print(Pessoa.apresentar())
  ```

  Saída real:

  ```text
  TypeError: Pessoa.apresentar() missing 1 required positional argument: 'self'
  ```

  O erro acontece porque `apresentar` precisa do objeto para receber `self`. A correção é criar uma instância: `p = Pessoa(); print(p.apresentar())`.
</Callout>

<Callout type="erro-comum" title="Atributo compartilhado entre objetos">
  ```python
  class Carrinho:
      itens = []

      def adicionar(self, item):
          self.itens.append(item)

  c1 = Carrinho()
  c2 = Carrinho()
  c1.adicionar("maçã")
  print(c2.itens)
  ```

  Saída real:

  ```text
  ['maçã']
  ```

  O problema é que `itens` foi criado como atributo da classe e não de cada objeto. A correção é criar a lista em `__init__` com `self.itens = []`.
</Callout>

No mercado de trabalho

Em backend, em sistemas financeiros, em APIs e em automações, a modelagem de domínio é muito valorizada. Quando você cria classes com nomes claros e responsabilidades bem definidas, o código fica mais fácil de evoluir, testar e manter. Isso é essencial em projetos reais, especialmente quando o sistema cresce e várias pessoas passam a trabalhar no mesmo código.
