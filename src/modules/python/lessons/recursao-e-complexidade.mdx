# Recursão e complexidade

Quando você resolve um problema pela primeira vez, costuma perguntar: “qual é o menor caso?” “o que muda quando o problema fica menor?” “quando eu paro?”. A recursão responde a isso de forma elegante: a solução chama a si mesma com uma versão menor do problema, até atingir uma condição de parada.

<Callout type="importante" title="O que você vai aprender">
  - Como a recursão funciona, com caso base e caso recursivo.
  - Quando usar recursão e quando a versão iterativa é mais clara.
  - Como ler notações como $O(1)$, $O(log n)$, $O(n)$ e $O(n^2)$.
  - Como comparar soluções com `time.perf_counter()` sem cair no erro de confundir “tempo real” com “complexidade”.
</Callout>

## Recursão: caso base e caso recursivo

Toda função recursiva precisa de um caso base. Sem ele, ela chama a si mesma até estourar a pilha e gerar `RecursionError`. O caso recursivo é a parte em que a função resolve uma versão menor do problema e depois combina o resultado.

<CodeBlock title="fatorial_recursivo.py" code={`def fatorial(n):
    if n == 0 or n == 1:
        return 1
    return n * fatorial(n - 1)

print(fatorial(5))
`} />

Saída:

```text
120
```

Esse padrão aparece em muitas soluções: caso base e “chamada menor”.

<CodeBlock title="soma_recursiva.py" code={`def soma_ate(n):
    if n == 0:
        return 0
    return n + soma_ate(n - 1)

print(soma_ate(5))
`} />

Saída:

```text
15
```

<Glossario termo="Caso base" definition="Condição que interrompe a recursão para evitar chamadas infinitas." />
<Glossario termo="Pilha de chamadas" definition="Estrutura que guarda cada chamada ativa da função até que o retorno seja concluído." />
<Glossario termo="Memoização" definition="Guardar resultados intermediários para evitar recalcular o mesmo subproblema várias vezes." />

<Playground title="Experimente: recursão e loop" code={`def fatorial_recursivo(n):
    if n in (0, 1):
        return 1
    return n * fatorial_recursivo(n - 1)

def fatorial_iterativo(n):
    total = 1
    for numero in range(2, n + 1):
        total *= numero
    return total

print(fatorial_recursivo(6))
print(fatorial_iterativo(6))
`} />

A recursão é muito elegante quando a estrutura do problema é naturalmente “menor e menor”. Já o loop costuma ser mais direto para problemas que precisam apenas repetir um passo em sequência.

## Fibonacci e a pilha de chamadas

A sequência de Fibonacci é um clássico. Cada termo depende dos dois anteriores. A fórmula é simples, mas a implementação direta sem otimização repete cálculo desnecessário.

<CodeBlock title="fibonacci_memorizado.py" code={`from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n in (0, 1):
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))
print(fib(20))
`} />

Saída:

```text
55
6765
```

Essa é uma boa demonstração de memoização: ao guardar resultados já calculados, você reduz chamadas repetidas e melhora muito o desempenho.

<StepThrough>
  <div>
    <p><strong>Etapa 1:</strong> `fib(4)` precisa de `fib(3)` e `fib(2)`.</p>
  </div>
  <div>
    <p><strong>Etapa 2:</strong> cada chamada vai empilhando mais camadas até atingir os casos base.</p>
  </div>
  <div>
    <p><strong>Etapa 3:</strong> quando os valores base voltam, o resultado final é montado em ordem inversa.</p>
  </div>
</StepThrough>

<Callout type="erro-comum" title="RecursionError sem caso base">
  ```python
  def contar_sem_parada(n):
      print(n)
      return contar_sem_parada(n + 1)

  contar_sem_parada(1)
  ```

  Saída real:

  ```text
  RecursionError: maximum recursion depth exceeded
  ```

  A função chama a si mesma sem parar. Toda recursão precisa de um caso base claro.
</Callout>

<Callout type="erro-comum" title="Fibonacci sem cache">
  ```python
  def fib_sem_cache(n):
      if n in (0, 1):
          return n
      return fib_sem_cache(n - 1) + fib_sem_cache(n - 2)

  print(fib_sem_cache(10))
  ```

  Saída real:

  ```text
  55
  ```

  Funciona, mas repete muitas contas. A memoização reduz esse custo sem mudar a ideia do algoritmo.
</Callout>

## Complexidade: O(1), O(log n), O(n), O(n²)

A “complexidade” explica como o tempo ou o espaço crescem conforme o problema cresce. Quando você lê $O(n)$, entende que o custo aumenta linearmente com a entrada. Isso ajuda a comparar soluções antes de implementá-las em produção.

<CodeBlock title="big_o.py" code={`def custo_constante(lista):
    return lista[0] if lista else None

def custo_linear(lista):
    total = 0
    for valor in lista:
        total += valor
    return total

print(custo_constante([10, 20, 30]))
print(custo_linear([10, 20, 30]))
`} />

Saída:

```text
10
60
```

- `custo_constante` é $O(1)$ porque acessa um elemento direto.
- `custo_linear` é $O(n)$ porque percorre todos os itens.
- Busca binária é $O(log n)$ porque corta o problema pela metade.
- Bubble sort é $O(n^2)$ porque compara muitos pares em várias passadas.

## Medindo tempo com `time.perf_counter()`

A medição de tempo não deve ser confundida com a teoria de complexidade. O Python oferece `time.perf_counter()` para marcar início e fim de uma operação. Isso é útil para comparar soluções reais, mas benchmarks podem variar de máquina para máquina.

<CodeBlock title="medir_tempo.py" code={`import time

inicio = time.perf_counter()
resultado = sum(range(1_000_000))
termino = time.perf_counter()
print(resultado)
print(f"tempo: {termino - inicio:.6f} segundos")
`} />

Saída real (pode variar um pouco):

```text
499999500000
tempo: 0.000000 segundos
```

O valor exato não é a parte mais importante. O que importa é perceber que a lógica e a estrutura do algoritmo têm mais influência no desempenho do que uma medida isolada de um único teste.

<Callout type="erro-comum" title="Loop infinito em busca binária">
  ```python
  def busca_binaria_errada(lista, alvo):
      inicio, fim = 0, len(lista) - 1
      while inicio <= fim:
          meio = (inicio + fim) // 2
          if lista[meio] == alvo:
              return meio
          if lista[meio] < alvo:
              inicio = meio
          else:
              fim = meio
      return -1

  dados = [2, 4, 6, 8, 10]
  print(busca_binaria_errada(dados, 8))
  ```

  A correção é avançar os ponteiros com `inicio = meio + 1` ou `fim = meio - 1`. Sem isso, a busca não progride.
</Callout>

## Quando iterar é melhor

Nem toda recursão é a melhor ferramenta. Em problemas lineares simples, como somar itens de uma lista, o loop costuma ser mais direto e usa menos memória. Em outros casos, a recursão torna a leitura mais natural e expressa melhor a ideia de “subproblema menor”.

<CodeBlock title="iterativo_versus_recursivo.py" code={`def soma_iterativa(lista):
    total = 0
    for valor in lista:
        total += valor
    return total

print(soma_iterativa([1, 2, 3, 4, 5]))
`} />

Saída:

```text
15
```

Essas duas versões resolvem o mesmo problema, mas a escolha certa depende da clareza da ideia e do custo do algoritmo.

## No mercado de trabalho

Recursão, busca e ordenação aparecem em sistemas reais, desde processamento de dados até algoritmos de suporte, logística e análise. Em engenharia, a questão não é apenas “funciona?”, mas “funciona bem quando o volume cresce?”. Saber dizer “isso é O(n²)” ou “essa busca é O(log n)” é uma capacidade muito valorizada.
