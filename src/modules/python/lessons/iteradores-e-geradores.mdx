# Iteradores e geradores

Você já viu que Python funciona muito bem com listas, dicionários e conjuntos. Mas nem sempre a melhor solução é “carregar tudo em memória”. Em alguns casos, você quer processar dados aos poucos, sem criar uma cópia inteira do conjunto. É aí que entram iteradores e geradores: estruturas que entregam valores sob demanda.

Imagine um script que lê milhões de registros de vendas ou analisa uma sequência enorme de números. Criar uma lista com tudo isso pode consumir muita memória e deixar o programa lento. Em vez disso, o código pode consumir cada item no momento em que ele é necessário.

## 1. Iterável e iterador são coisas diferentes

Listas, strings, tuplas e dicionários são iteráveis. Isso significa que você consegue percorrer cada elemento com um `for`. Mas o objeto que de fato entrega esses valores um a um é o iterador.

<CodeBlock title="iterador_basico.py" code={`lista = [10, 20, 30]
it = iter(lista)
print(type(it))
print(next(it))
print(next(it))
print(next(it))`} />

A saída é algo como `'<list_iterator object at ...>'`, seguida de `10`, `20` e `30`. O `iter(lista)` transforma a lista em um objeto iterador. A cada `next()`, Python entrega o próximo valor.

## 2. Você pode percorrer um iterador apenas uma vez

Um detalhe importante: um iterador guarda o estado atual de avanço. Depois de consumir todos os valores, ele acaba.

<CodeBlock title="iterador_consumido.py" code={`it = iter('abc')
print(next(it))
print(next(it))
print(next(it))
print(next(it))`} />

A última chamada `next(it)` dispara `StopIteration`. Isso é a forma natural de Python dizer: “não há mais itens”. O loop `for` captura isso e para a iteração automaticamente.

## 3. Geradores: produção sob demanda

Uma função com `yield` vira um gerador. Em vez de devolver um único valor e encerrar, ela entrega um valor e pausa, esperando que o próximo `next()` peça o próximo item.

<CodeBlock title="gerador_soma.py" code={`def numeros_ate(n):
    for i in range(1, n + 1):
        yield i

for numero in numeros_ate(5):
    print(numero)`} />

A saída é:

```text
1
2
3
4
5
```

A função `numeros_ate` não retorna uma lista pronta; ela produz elementos conforme o consumidor pede. Isso economiza memória quando a sequência pode ser longa.

Você também pode criar geradores com expressão geradora, parecida com comprehension, mas sem guardar todos os valores de uma vez.

<CodeBlock title="expressao_geradora.py" code={`quadrados = (n * n for n in range(1, 6))
print(next(quadrados))
print(next(quadrados))
print(list(quadrados))`} />

A saída é `1`, `4` e `[9, 16, 25]`.

## 4. Geradores economizam memória

Uma lista inteira ocupa espaço em memória. Um gerador, por outro lado, produz o próximo item quando necessário.

<CodeBlock title="comparando_memoria.py" code={`lista = [n for n in range(1_000_000)]
print(lista[:5])

def gerador():
    for n in range(1_000_000):
        yield n

print(next(gerador()))
print(next(gerador()))`} />

Isso não mostra consumo de memória diretamente, mas ilustra a diferença conceitual. A lista inteira existe; o gerador entrega valores sob demanda.

<Playground title="Experimente: gerar números pares sob demanda" code={`def pares_ate(n):
    for numero in range(n + 1):
        if numero % 2 == 0:
            yield numero

for valor in pares_ate(10):
    print(valor)`} />

## 5. O gerador “esvazia” quando é consumido

Esse é um erro clássico: você cria um gerador, passa por ele uma vez e depois tenta usá-lo de novo. Como ele não guarda os dados em memória, a segunda passagem não retorna nada.

<Callout type="erro-comum" title="Erro: gerador esvazia">
  O gerador pode ser consumido uma só vez.
  <CodeBlock title="gerador_esvaziado.py" code={`gerador = (n for n in range(3))
print(list(gerador))
print(list(gerador))`} />
  A saída real é `[0, 1, 2]` e depois `[]`. A segunda chamada não fornece nada porque o gerador já foi consumido.
</Callout>

Esse comportamento é natural e é exatamente o que torna o gerador eficiente. Se você precisa reusar a sequência, converta para lista ou tuple antes de iterar novamente.

## 6. `reversed`, iteração e fluxo de dados

Além de `iter` e `yield`, Python oferece vários mecanismos para trabalhar com sequências de forma elegante. `reversed()` permite percorrer uma lista ou string do fim para o começo sem mexer na estrutura original.

<CodeBlock title="reversed.py" code={`texto = 'python'
for letra in reversed(texto):
    print(letra)`} />

A saída é cada letra em ordem invertida:

```text
n
o
h
t
y
p
```

### No mercado de trabalho

Em processamento de dados, logs, ETL e integrações, você quase sempre trabalha com sequências grandes. Geradores evitam que o programa gere listas enormes só para consumir algumas partes. Isso é especialmente importante em painéis de análise e pipelines de dados.

<Resumo>
  <li>Iteráveis podem ser percorridos; iteradores entregam valores passo a passo.</li>
  <li>Geradores usam `yield` para produzir sequência sob demanda.</li>
  <li>Expressões geradoras são mais leves do que listas quando a sequência é grande.</li>
  <li>Geradores se esgotam após uma iteração; para reutilizar, converta em lista ou tuple.</li>
  <li>Fluxos de dados sob demanda ajudam a economizar memória e melhorar performance.</li>
