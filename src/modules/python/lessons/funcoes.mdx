# Funções

Você já viu que Python aceita instruções em sequência, mas quando o programa cresce, repetir trechos quase iguais vira manutenção difícil. Imagine um sistema de cadastro que precisa cumprimentar clientes, calcular descontos em vários lugares e validar nomes em diferentes telas. Em vez de copiar o mesmo bloco, você encapsula a lógica em uma função: um nome, um comportamento e um resultado previsível.

Isso muda o jeito de pensar em programação. Você deixa o código mais legível, mais testável e mais fácil de reutilizar. A ideia central é simples: uma função recebe entradas, processa elas e devolve um valor quando faz sentido.

## 1. Definindo uma função

A sintaxe começa com `def`, seguida do nome e parênteses. Dentro da função, você escreve o bloco de instruções. Quando a função é chamada, a execução salta para esse trecho e volta para o ponto de origem depois do `return`.

<CodeBlock title="saudacao.py" code={`def saudacao(nome):
    return f"Olá, {nome}!"

print(saudacao("Lia"))
print(saudacao("Pedro"))`} />

O código acima imprime duas saudações. A função `saudacao` recebe uma entrada chamada `nome` e devolve uma string pronta para ser impressa. Veja a lógica: a função não “escreve no console” por conta própria; ela retorna um valor que o programa usa depois.

A primeira vantagem é a reutilização. Você não precisa repetir aquele trecho de mensagem em vários lugares. Em vez disso, chama a função toda vez que quiser. Outra vantagem é testar isoladamente. Se a função está certa, seu comportamento fica previsível.

## 2. `return` vs `print`

Essa é uma confusão muito comum no começo. `print` apenas exibe algo para o usuário. `return` entrega um valor para quem chamou a função. Isso importa porque a função pode gerar um resultado que outro pedaço do programa usa como entrada de outra operação.

<CodeBlock title="print_vs_return.py" code={`def imprimir_soma(a, b):
    print(a + b)

def devolver_soma(a, b):
    return a + b

imprimir_soma(10, 5)
resultado = devolver_soma(10, 5)
print(resultado)
print(devolver_soma(20, 7))`} />

A função `imprimir_soma` mostra o total na tela, mas não o devolve. Já `devolver_soma` produz um valor útil para armazenar em variável ou passar para outra expressão. A saída mostra isso claramente.

<StepThrough>
  <div>
    <strong>Passo 1:</strong> o programa chama <code>imprimir_soma(10, 5)</code>. A função executa <code>print(a + b)</code> e mostra 15.
  </div>
  <div>
    <strong>Passo 2:</strong> a função <code>devolver_soma(10, 5)</code> calcula 15, mas em vez de mostrar na tela, entrega esse valor para a variável <code>resultado</code>.
  </div>
  <div>
    <strong>Passo 3:</strong> a expressão <code>print(resultado)</code> mostra 15 novamente, e a próxima chamada usa esse valor em outra operação.
  </div>
</StepThrough>

A regra prática é: use `print` quando você quer mostrar algo para o usuário; use `return` quando você quer produzir um valor para o restante do programa. Se uma função não retorna nada, ela normalmente retorna `None` implicitamente.

## 3. Parâmetros, argumentos e valores padrão

Uma função geralmente recebe entradas em forma de parâmetros. No momento da chamada, você passa argumentos. Quando você define um valor padrão, a função consegue funcionar mesmo sem o argumento ser informado.

<CodeBlock title="parametros_padrao.py" code={`def calcular_desconto(preco: float, percentual: float = 10) -> float:
    return preco * (1 - percentual / 100)

print(calcular_desconto(200))
print(calcular_desconto(200, 25))
print(calcular_desconto(percentual=15, preco=100))`} />

Aqui, o parâmetro `percentual` tem valor padrão de `10`. Se o argumento não for passado, o código usa esse valor. A chamada com argumentos nomeados também funciona porque Python permite que você diga explicitamente qual valor vai para qual nome. Isso melhora a legibilidade, especialmente em funções com muitos parâmetros.

Você também pode escrever funções mais flexíveis usando parâmetros opcionais ou nomes autoexplicativos. O importante é manter a assinatura clara: o que a função recebe e o que devolve.

## 4. Docstrings e type hints

Documentar uma função não é luxo: é uma forma de deixar o contrato da função inteligível. A docstring é uma string curta logo no início da função, explicando o que ela faz. Já os `type hints` dizem ao Python e a você qual tipo cada parâmetro e retorno deve ter.

<CodeBlock title="docstring_e_type_hints.py" code={`def media(numeros: list[float]) -> float:
    """Calcula a média aritmética de uma lista de números."""
    return sum(numeros) / len(numeros)

print(media([8.0, 10.0, 6.0]))
print(media([5.0, 7.0, 9.0, 11.0]))`} />

A docstring descreve a intenção da função, e os type hints deixam a API mais clara para quem lê o código. Isso ajuda em manutenção, revisão e na própria experiência de desenvolvimento. Em projetos maiores, isso reduz erros e facilita a leitura rápida.

    """Gera uma linha de resumo do pedido."""
    return f"{nome_cliente}: {', '.join(itens)}"

print(resumo_pedido("Maria", ["pão", "leite", "ovos"]))`} />

## 5. Quando uma função é útil?

Funções são especialmente valiosas quando você precisa dividir responsabilidades. Em vez de um programa enorme, com tudo misturado, você organiza blocos com propósito único. Isso facilita a leitura, a depuração e a reutilização. Uma função pura, por exemplo, recebe dados e retorna um resultado sem modificar estado externo; já uma função com efeito colateral pode alterar uma variável global, salvar arquivo ou atualizar um contador.

Você não precisa transformar tudo em função imediatamente. O princípio é separar trechos que têm nomes claros e fazem uma ação específica. Se você consegue dizer em uma frase o que a função faz, ela provavelmente está bem definida.

<Callout type="erro-comum" title="Erro: função retorna None">
  O problema aparece quando você cria uma função sem `return` e espera um valor de volta. Em vez de receber um resultado, você recebe `None`.
  <CodeBlock title="erro_none.py" code={`def mensagem(nome):
    print(f"Olá, {nome}!")

resultado = mensagem("Lia")
print(resultado)`} />
  A mensagem real do programa é a saída em que `resultado` aparece como `None`. A correção é retornar o valor quando a função deveria produzir algo, e não só exibí-lo.
</Callout>

<Callout type="erro-comum" title="Erro: modificar variável global sem declarar">
  Quando uma função tenta alterar uma variável externa sem receber o valor como parâmetro, Python cria uma variável local e você vê `UnboundLocalError`.
  <CodeBlock title="erro_unbound.py" code={`contador = 1

def aumentar():
    contador = contador + 1
    return contador

print(aumentar())`} />
  A mensagem real é `UnboundLocalError: local variable 'contador' referenced before assignment`. A correção é receber o valor por parâmetro e devolver o resultado, em vez de tentar mexer no dado externo sem avisar explicitamente ao Python.
</Callout>

<Callout type="erro-comum" title="Erro: valor padrão mutável">
  Esse é um clássico de funções. Quando você usa uma lista como valor padrão, ela fica “presa” à função entre chamadas.
  <CodeBlock title="erro_default_mutavel.py" code={`def registrar(item, itens=[]):
    itens.append(item)
    return itens

print(registrar("a"))
print(registrar("b"))`} />
  A saída real mostra que a segunda chamada reaproveita a lista da primeira: `['a']` e `['a', 'b']`. A correção é usar `None` e criar a lista dentro da função, se a intenção for um estado novo a cada chamada.
</Callout>

### No mercado de trabalho

Funções são a base da organização de código em projetos reais. Em APIs, scripts de automação, ferramentas de análise e sistemas grandes, elas são usadas para separar regras de negócio, validar dados, calcular resultados e reaproveitar lógica entre módulos. Um código com funções bem pensadas é mais fácil de testar, menos sujeito a erro e mais simples de evoluir quando o projeto cresce.

Em uma empresa, você geralmente encontra funções que validam campos, calculam frete, geram relatórios e extraem dados. Nessa prática, uma boa função tem nome claro, poucas responsabilidades e retorno previsível. Isso é o que torna um sistema fácil de manter e de auditar.
