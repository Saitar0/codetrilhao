# Dataclasses e enums

Depois de aprender a criar classes, atributos, herança e métodos especiais, chega a hora de trabalhar com estruturas que aparecem muito em código de produção. O objetivo agora é escrever menos boilerplate e deixar claro o que cada modelo representa. É aí que entram as `dataclasses` e os `Enum`.

Uma `dataclass` é uma classe focada em dados. Em vez de escrever manualmente `__init__`, `__repr__` e comparações simples, o Python gera isso para você. Já um `Enum` representa um conjunto finito de valores possíveis, como status de pedido, tipos de pagamento ou nível de prioridade.

## `dataclass`: menos boilerplate, mais clareza

Uma classe de dados geralmente guarda atributos e pouco mais. Ela não precisa de lógica complexa; precisa apenas representar um valor. A `dataclass` faz esse trabalho automaticamente.

```python
from dataclasses import dataclass

@dataclass
class Produto:
    nome: str
    preco: float
    em_estoque: int = 0

p = Produto("Caneta", 4.90, 12)
print(p)
print(p.preco)
```

Saída:

```text
Produto(nome='Caneta', preco=4.9, em_estoque=12)
4.9
```

Essa representação já é bem mais útil do que um objeto genérico. A classe fica legível e você ganha automaticamente a representação em texto e comparações básicas.

## `frozen`, `default_factory` e representações úteis

`dataclass` também aceita opções úteis. Por exemplo, `frozen=True` impede que os atributos sejam modificados depois da criação. Isso é interessante quando você quer um valor imutável.

```python
from dataclasses import dataclass, field

@dataclass(frozen=True)
class Item:
    nome: str
    quantidade: int = 1
    tags: list[str] = field(default_factory=list)

item = Item("Notebook", 1, ["eletrônico", "novo"])
print(item)
```

Saída:

```text
Item(nome='Notebook', quantidade=1, tags=['eletrônico', 'novo'])
```

Essa combinação deixa a classe clara e segura. O uso de `default_factory` é especialmente importante quando o valor padrão é um objeto mutável, como uma lista.

## `Enum`: estados bem definidos

Quando um dado só pode assumir um conjunto finito de valores, `Enum` é a escolha mais clara. Ele evita que strings arbitrárias e textos soltos entrem no sistema com valores inconsistente.

```python
from enum import Enum

class StatusPedido(Enum):
    PENDENTE = "pendente"
    PAGO = "pago"
    ENVIADO = "enviado"

print(StatusPedido.PENDENTE)
print(StatusPedido.PENDENTE.value)
```

Saída:

```text
StatusPedido.PENDENTE
pendente
```

Agora você não precisa perguntar “qual foi a string usada?” a cada vez. O código usa valores nomeados e explícitos, o que reduz erros de digitação e melhora a legibilidade.

## `@classmethod` e `@staticmethod`

Nem toda operação de uma classe precisa agir sobre um objeto específico. Por isso existem métodos de classe e métodos estáticos.

- `@classmethod`: opera sobre a classe, e não sobre a instância.
- `@staticmethod`: não depende nem da instância nem da classe; é apenas uma função organizada dentro da classe.

```python
class Usuario:
    total = 0

    def __init__(self, nome):
        self.nome = nome
        Usuario.total += 1

    @classmethod
    def quantidade(cls):
        return cls.total

    @staticmethod
    def formatar_nome(nome):
        return nome.strip().title()

u1 = Usuario("  ana  ")
u2 = Usuario("pedro")
print(Usuario.quantidade())
print(Usuario.formatar_nome("  bia  "))
```

Saída:

```text
2
Bia
```

A diferença é importante: o método de classe conhece a própria classe; o método estático apenas encapsula uma funcionalidade útil no contexto da classe.

## Serialização em JSON com `json`

Em muitos programas, você precisa transformar um objeto em texto para guardar ou trocar informações. O módulo `json` transforma estruturas Python em JSON em memória. Isso é comum em APIs, arquivos de configuração e otimização de armazenamento local.

```python
import json
from dataclasses import dataclass

@dataclass
class Cliente:
    nome: str
    ativo: bool

cliente = Cliente("Lia", True)
texto = json.dumps(cliente.__dict__)
print(texto)
objeto = json.loads(texto)
print(objeto["nome"])
```

Saída:

```text
{"nome": "Lia", "ativo": true}
Lia
```

Esse padrão é simples e muito usado. O ponto importante é que você serializa os dados do objeto, não o comportamento. O código de lógica continua dentro da classe; o JSON só transporta o estado do objeto em memória.

## Princípios de projeto e responsabilidade

Ao final do tópico 16, a ideia central não é apenas “saber sintaxe”. É entender que classes devem refletir o domínio de forma clara. Isso significa: responsabilidade única, baixo acoplamento e regras bem definidas. Se a classe faz tudo ao mesmo tempo, ela fica difícil de manter.

Em outras palavras, uma classe deve ter uma razão de existir e uma ideia clara de quem ela representa. Isso também vale para `dataclasses` e `Enum`: eles ajudam a deixar o modelo mais expressivo, sem inventar complexidade desnecessária.

<Callout type="erro-comum" title="Criar dataclass com lista mutável sem default_factory">
  ```python
  from dataclasses import dataclass

  @dataclass
  class Pedido:
      itens: list

  p1 = Pedido([])
  p2 = Pedido([])
  p1.itens.append("café")
  print(p2.itens)
  ```

  Saída real:

  ```text
  ['café']
  ```

  Isso acontece porque a lista padrão é compartilhada entre instâncias. O uso de `field(default_factory=list)` corrige isso.
</Callout>
