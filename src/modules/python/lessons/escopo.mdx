# Escopo

Ao definir funções, você logo percebe que nem toda variável funciona do mesmo jeito em todos os lugares. Isso acontece porque Python organiza o acesso a nomes em camadas. Uma variável pode ser local a uma função, global ao módulo, ou capturada de um bloco externo. Esse comportamento é o que chamamos de escopo.

Sem entender escopo, você pode tentar alterar uma variável em um lugar que o Python interpreta de forma diferente, e isso leva a erros como `UnboundLocalError` ou a comportamentos estranhos. Mas o bom é que o mecanismo é previsível. Em Python, o acesso a nomes segue a regra LEGB: Local, Enclosing, Global, Built-in.

## 1. Escopo local e global

Quando você cria uma variável dentro de uma função, ela normalmente é local a essa função. Quando você cria no nível do módulo, ela é global.

<CodeBlock title="escopo_local_global.py" code={`valor = "global"

def mostrar():
    valor = "local"
    print("Dentro da função:", valor)

mostrar()
print("Fora da função:", valor)`} />

A saída mostra que a variável `valor` dentro da função não mexe na variável externa. Isso ocorre porque a função cria um novo espaço de nomes. Em Python, nomes locais têm prioridade sobre nomes globais dentro da função.

Mas se uma função tenta modificar uma variável global sem avisar explicitamente, isso muda o quadro. O Python então assume que a variável é local se você houver uma atribuição dentro dela. Isso é a causa da famosa `UnboundLocalError`.

## 2. O que a regra LEGB faz

Python resolve nomes seguindo essa ordem:

1. Local: nomes definidos dentro da função atual.
2. Enclosing: nomes das funções externas que envolvem a função atual.
3. Global: nomes definidos no módulo.
4. Built-in: nomes já disponíveis como `print`, `len`, `sum` e outros.

<CodeBlock title="legb.py" code={`mensagem = "global"

def externa():
    mensagem = "enclosing"

    def interna():
        print(mensagem)

    interna()

externa()`} />

Nesse exemplo, a função `interna` encontra `mensagem` no escopo da função `externa` antes de procurar no módulo. Isso é o nível “enclosing”. Quando você entende essa ordem, fica mais fácil prever como o Python acessa os nomes.

## 3. Quando `global` faz sentido — e quando não faz

Você pode usar `global` para sinalizar que uma variável definida fora da função deve ser modificada no próprio escopo global. Isso é útil em scripts pequenos, mas em programas organizados isso costuma ser evitado.

<CodeBlock title="global.py" code={`contador = 0

def aumentar():
    global contador
    contador += 1
    print(contador)

aumentar()
aumentar()
print(contador)`} />

A linha `global contador` informa ao Python: “não crie uma variável local; use a global”. Isso funciona, mas é uma prática que pode dificultar a leitura e o raciocínio. Em código modular e organizado, o melhor é passar valores como parâmetros e devolver resultados como retorno. Isso reduz efeitos colaterais e torna a função mais previsível.

<StepThrough>
  <div>
    <strong>Passo 1:</strong> `contador` começa com 0 no escopo global.
  </div>
  <div>
    <strong>Passo 2:</strong> quando `aumentar()` é chamada, `global contador` aponta para a variável global e a incrementa.
  </div>
  <div>
    <strong>Passo 3:</strong> depois da segunda chamada, o valor global foi modificado e continua visível fora da função.
  </div>
</StepThrough>

A recomendação mais segura é evitar `global` quando a função pode receber o valor por parâmetro e devolver um resultado. Isso deixa a relação entre entrada e saída muito mais clara.

## 4. Closures

Uma closure é uma função que “lembra” variáveis do escopo em que foi criada, mesmo depois que essa função externa terminou de executar. Isso cria um comportamento interessante: a função interna continua acessando valores de fora.

<CodeBlock title="closure.py" code={`def multiplicar_por(fator):
    def interno(numero):
        return numero * fator
    return interno

triplicar = multiplicar_por(3)
print(triplicar(4))
print(triplicar(7))`} />

A função `interno` lembra o valor `fator` do ambiente em que foi criada. Em outras palavras, `triplicar` continua usando `3` mesmo depois que `multiplicar_por` concluiu. Isso é útil para criar funções especializadas e simplificar padrões de configuração.

Você encontra closures em bibliotecas e em código que encapsula comportamento recorrente. Elas são um conceito importante para entender como o Python preserva estado em um ambiente menor sem depender de variáveis globais.

## 5. Por que evitar `global`?

Além de dificultar leitura, `global` torna a função menos reutilizável e mais dependente do ambiente externo. Quando a função depende de estado global, você precisa lembrar de toda a história da variável para entender o comportamento dela. Em projetos reais, isso torna testes e depuração mais complexos.

O melhor design é: a função recebe dados e retorna um valor. Em vez de você mexer em um estado escondido no módulo, você produz um resultado explícito. Essa clareza é valiosa porque facilita revisão de código e ajuda durante a manutenção.

<Callout type="erro-comum" title="Erro: `UnboundLocalError` ao alterar variável global">
  O problema aparece quando a função tenta modificar uma variável global sem declarar `global`.
  <CodeBlock title="erro_unbound_escopo.py" code={`total = 0

def adicionar(valor):
    total = total + valor
    return total

print(adicionar(5))`} />
  A mensagem real é `UnboundLocalError: local variable 'total' referenced before assignment`. O Python assume que `total` dentro da função é local, então tenta usar antes de atribuir. A correção é declarar `global total` ou, melhor ainda, receber o valor e devolver o resultado.
</Callout>

<Callout type="erro-comum" title="Erro: usar `global` em excesso">
  A função fica acoplada ao estado do módulo e até difícil de testar isoladamente.
  <CodeBlock title="erro_global_excesso.py" code={`saldo = 100

def sacar(valor):
    global saldo
    saldo = saldo - valor

sacar(30)
print(saldo)`} />
  Isso funciona, mas o efeito colateral fica menos transparente. A forma mais previsível é `def sacar(saldo, valor): return saldo - valor` e então decidir no código externo como atualizar a variável.
</Callout>

<Callout type="erro-comum" title="Erro: esperar que closure use variável local depois do fim">
  Closure funciona com variáveis capturadas, mas isso depende do ambiente em que a função foi criada.
  <CodeBlock title="erro_closure.py" code={`def criar_contador():
    contador = 0
    def incrementar():
        contador += 1
        return contador
    return incrementar

c = criar_contador()
print(c())`} />
  A mensagem real é `UnboundLocalError: local variable 'contador' referenced before assignment`. O problema é que `contador += 1` cria uma variável local dentro da closure. Para corrigir, use `nonlocal contador`.
</Callout>

### No mercado de trabalho

Escopo é um assunto que aparece em qualquer linguagem com funções e módulos. Em projetos de backend, automação, scripts de processamento e sistemas de dados, você precisa pensar sobre quando uma variável pertence ao módulo e quando pertence à função. Isso impacta facilmente a manutenção, os testes e a qualidade do código.

Programadores experientes evitam depender de estado global porque isso cria acoplamento. Em vez disso, eles preferem funções que recebem entrada e devolvem saída. O domínio de escopo é parte do que separa código funcionalmente previsível de código que funciona “por acaso” dentro de um arquivo pequeno.
