# Herança e polimorfismo

Você já aprendeu que classes representam entidades e que cada objeto pode ter estado próprio. Agora vem um passo importante: como evitar duplicação de código quando várias classes compartilham a mesma ideia. A resposta é a herança.

A herança permite que uma classe filha reutilize atributos e métodos de uma classe pai. Isso reduz repetição e deixa o modelo mais organizado. Mas existe um cuidado: herança não é para tudo. Nem toda relação entre classes é “é um”. Às vezes, a melhor solução é composição.

## Herança: reaproveitar comportamento

Uma classe filha herda da classe pai. Isso significa que ela ganha atributos e métodos já definidos, e pode adicionar ou sobrescrever o que for necessário.

```python
class Animal:
    def __init__(self, nome):
        self.nome = nome

    def emitir_som(self):
        return "som genérico"

class Cachorro(Animal):
    def emitir_som(self):
        return "au au"

class Gato(Animal):
    def emitir_som(self):
        return "miau"

pets = [Cachorro("Rex"), Gato("Mimi")]
for pet in pets:
    print(f"{pet.nome}: {pet.emitir_som()}")
```

Saída:

```text
Rex: au au
Mimi: miau
```

A classe `Animal` define a base. `Cachorro` e `Gato` reutilizam a estrutura e sobrescrevem o método `emitir_som` para produzir sons diferentes. Isso é o que chamamos de sobrescrita.

## `super()` e a lógica da classe base

Quando uma classe filha precisa complementar o comportamento do pai, o `super()` ajuda a chamar a implementação da classe base sem repetir todo o código.

```python
class Funcionario:
    def __init__(self, nome, salario):
        self.nome = nome
        self.salario = salario

    def resumo(self):
        return f"{self.nome}: R$ {self.salario:.2f}"

class Gerente(Funcionario):
    def __init__(self, nome, salario, departamento):
        super().__init__(nome, salario)
        self.departamento = departamento

    def resumo(self):
        return f"{super().resumo()} | Departamento: {self.departamento}"

manager = Gerente("Lia", 5000, "TI")
print(manager.resumo())
```

Saída:

```text
Lia: R$ 5000.00 | Departamento: TI
```

A classe `Gerente` reutiliza o que já existe em `Funcionario`, mas adiciona informação específica do departamento. Isso é uma solução muito comum quando o modelo do domínio tem hierarquias claras.

## Polimorfismo: mesma interface, comportamentos diferentes

O polimorfismo aparece quando objetos de diferentes classes respondem ao mesmo método de maneira específica. Em outras palavras, você pode chamar um método comum em vários tipos e cada um executa sua própria lógica.

```python
class Forma:
    def area(self):
        raise NotImplementedError("Subclasse deve implementar area()")

class Quadrado(Forma):
    def __init__(self, lado):
        self.lado = lado

    def area(self):
        return self.lado ** 2

class Circulo(Forma):
    def __init__(self, raio):
        self.raio = raio

    def area(self):
        return 3.14159 * self.raio ** 2

formas = [Quadrado(4), Circulo(3)]
for forma in formas:
    print(forma.area())
```

Saída:

```text
16
28.27431
```

Mesmo sendo tipos diferentes, ambas as classes atendem à mesma interface: o método `area()`. Isso permite que você trate os objetos por um conceito comum sem escrever lógica quebrada para cada caso individual.

## Herança x composição

Aqui entra uma decisão importante: “é um” ou “tem um”? A herança é adequada quando a relação é clara de subclasse: `Gato` é um `Animal`, `Gerente` é um `Funcionario`. Já a composição é melhor quando a classe usa outra classe como parte de si, sem ser um tipo compatível.

```python
class Motor:
    def ligar(self):
        return "motor ligado"

class Carro:
    def __init__(self):
        self.motor = Motor()

    def iniciar(self):
        return self.motor.ligar()

carro = Carro()
print(carro.iniciar())
```

Saída:

```text
motor ligado
```

O carro “tem um” motor, mas não é um motor. Essa distinção impede hierarquias artificiais e torna o código mais sustentável.

<Callout type="erro-comum" title="Herança para tudo">
  ```python
  class Livro:
      def __init__(self, titulo):
          self.titulo = titulo

  class Kindle(Livro):
      pass

  print(isinstance(Kindle("Python"), Livro))
  ```

  Saída real:

  ```text
  True
  ```

  Isso funciona, mas a relação pode ser artificial. O problema é usar herança para representar “tem um” quando a ideia correta é composição. Nem toda relação de uso deve virar herança.
</Callout>

<Callout type="erro-comum" title="Super sem chamar a classe base">
  ```python
  class Funcionario:
      def __init__(self, nome):
          self.nome = nome

  class Gerente(Funcionario):
      def __init__(self, nome, setor):
          self.setor = setor

  g = Gerente("Bia", "Vendas")
  print(g.nome)
  ```

  Saída real:

  ```text
  AttributeError: 'Gerente' object has no attribute 'nome'
  ```

  A classe filha não inicializou a parte herdada. A correção é usar `super().__init__(nome)` antes de acessar atributos do pai.
</Callout>

No mercado de trabalho

Herança e polimorfismo aparecem muito em sistemas com regras de negócio, cadastros, regras de cálculo e APIs. Em código de backend, por exemplo, você pode ter `Funcionario`, `CLT`, `PJ` e `Estagiario` compartilham a mesma interface para calcular pagamento. Ao usar herança de forma correta, o sistema fica mais fácil de evoluir quando o domínio cresce.
