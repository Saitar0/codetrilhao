# SQLite básico

Você já aprendeu que APIs devolvem dados em JSON e que o código precisa lidar com essas respostas. Mas o que acontece quando você quer guardar esses dados para usar depois? A resposta é persistência. Em vez de perder tudo quando o programa termina, você salva os dados em um banco. O SQLite é a ferramenta mais simples para isso: ele é leve, fica em um arquivo local e não exige um servidor separado.

Quando você entende como criar uma tabela, inserir registros e consultar dados, você passa a ter a base para qualquer sistema que guarda clientes, pedidos, usuários, histórico de consultas ou arquivos de configuração. O importante é pensar em banco como estrutura organizada de informação, e não só como “arquivo que guarda dados”.

## 1. Tabela, linha e coluna

A primeira ideia do banco é semelhante a uma planilha. Uma tabela guarda linhas de dados; cada linha é um registro; cada coluna é um campo. Quando você cria uma tabela, define os campos e o tipo de cada um. A chave primária identifica cada registro de forma única, e isso ajuda a localizar, atualizar ou apagar um item específico.

Em SQLite, o passo mais comum é conectar ao banco e começar a criar a estrutura. Para estudos e exemplos, você pode usar `sqlite3.connect(":memory:")`, que cria um banco na memória e deixa o código simples de testar.

<CodeBlock title="sqlite_basico.py" code={`import sqlite3

conexao = sqlite3.connect(":memory:")
cursor = conexao.cursor()

cursor.execute(
    "CREATE TABLE usuarios (id INTEGER PRIMARY KEY, nome TEXT, idade INTEGER)"
)
cursor.execute(
    "INSERT INTO usuarios (nome, idade) VALUES (?, ?)",
    ("Ana", 30),
)
conexao.commit()

print(cursor.execute("SELECT nome, idade FROM usuarios").fetchall())`} />

Saída esperada:

```text
[('Ana', 30)]
```

Esse exemplo mostra o fluxo básico do SQLite: conectar, criar a tabela, inserir, confirmar e consultar. O `commit()` faz com que a alteração seja salva. Sem essa etapa, os dados podem ficar pendentes na transação e não aparecer para outra parte do programa.

<CodeBlock title="criar_produtos.py" code={`import sqlite3

conexao = sqlite3.connect(":memory:")
cur = conexao.cursor()

cur.execute("CREATE TABLE produtos (id INTEGER PRIMARY KEY, nome TEXT, preco REAL)")
cur.execute("INSERT INTO produtos (nome, preco) VALUES (?, ?)", ("Caneta", 7.5))
cur.execute("INSERT INTO produtos (nome, preco) VALUES (?, ?)", ("Caderno", 12.0))
conexao.commit()

for linha in cur.execute("SELECT id, nome, preco FROM produtos ORDER BY id"):
    print(linha)`} />

Saída esperada:

```text
(1, 'Caneta', 7.5)
(2, 'Caderno', 12.0)
```

Você está vendo a diferença entre “dados em memória” e “dados persistidos”. O banco deixa a informação organizada e pronta para ser consultada com filtros, ordenação e relatórios.

## 2. `INSERT`, `SELECT`, `WHERE`, `ORDER BY`, `UPDATE` e `DELETE`

Depois que a tabela existe, a parte mais útil é manipular registros. O `INSERT` salva; o `SELECT` lê; o `WHERE` filtra; o `ORDER BY` ordena; o `UPDATE` altera; o `DELETE` remove. Esse conjunto forma o núcleo do SQL.

Em sistemas reais, quase toda regra de negócio passa por alguma combinação desses comandos. Por exemplo: “mostre clientes com mais de 100 pontos”, “ordene por nome”, “altere o estado civil” ou “remova um cadastro antigo”.

<CodeBlock title="consultas_sql.py" code={`import sqlite3

conexao = sqlite3.connect(":memory:")
cur = conexao.cursor()
cur.execute("CREATE TABLE clientes (id INTEGER PRIMARY KEY, nome TEXT, pontos INTEGER)")
cur.executemany(
    "INSERT INTO clientes (nome, pontos) VALUES (?, ?)",
    [("Ana", 120), ("Bia", 80), ("Carlos", 150)],
)
conexao.commit()

print(cur.execute("SELECT nome, pontos FROM clientes WHERE pontos >= 100 ORDER BY pontos DESC").fetchall())
print(cur.execute("SELECT COUNT(*) FROM clientes").fetchone())`} />

Saída esperada:

```text
[('Carlos', 150), ('Ana', 120)]
(3,)
```

A consulta filtrou por uma condição e ordenou os resultados. Isso é extremamente útil em relatórios, jogos, rankings e qualquer sistema em que você precisa responder uma pergunta sobre os dados.

## 3. Persistência real: `commit` e transação

Uma confusão comum é achar que `INSERT` salva automaticamente. Nem sempre. O banco usa transações, e o `commit()` é o ponto de confirmação. Enquanto a transação não é confirmada, outra conexão pode não ver o dado. Isso é importante em sistemas reais, porque você pode ter duas partes do programa acessando o mesmo banco ao mesmo tempo.

O bloco `with sqlite3.connect(...) as con` ajuda a encapsular isso, porque o contexto fecha a conexão e salva as alterações quando o bloco termina. Em scripts simples, `commit()` explícito ainda é a forma mais clara de entender.

<CodeBlock title="commit_necessario.py" code={`import sqlite3

arquivo = "contatos.db"
con = sqlite3.connect(arquivo)
cur = con.cursor()
cur.execute("CREATE TABLE IF NOT EXISTS contatos (nome TEXT)")
cur.execute("INSERT INTO contatos VALUES (?)", ("Ana",))

print("Mesma conexão:", con.execute("SELECT * FROM contatos").fetchall())

outra = sqlite3.connect(arquivo)
print("Antes do commit:", outra.execute("SELECT * FROM contatos").fetchall())

con.commit()
print("Depois do commit:", outra.execute("SELECT * FROM contatos").fetchall())`} />

Saída esperada:

```text
Mesma conexão: [('Ana',)]
Antes do commit: []
Depois do commit: [('Ana',)]
```

Esse é um ponto importante: a mesma conexão enxerga o registro imediatamente, mas outra conexão só vê o dado depois do `commit()`. Em aplicações reais, isso vira um erro de lógica se você esquecer de confirmar.

## 4. Segurança e `JOIN` inicial

O SQL é poderoso, mas exige cuidado. Quando o texto de entrada entra na query por concatenação, você abre brecha para injeção de SQL. A forma segura é usar parâmetros: `?` no SQLite e uma tupla com os valores. Isso separa instrução de dado.

<CodeBlock title="sql_inseguro_vs_seguro.py" code={`import sqlite3

conexao = sqlite3.connect(":memory:")
cur = conexao.cursor()
cur.execute("CREATE TABLE usuarios (login TEXT)")
cur.executemany("INSERT INTO usuarios (login) VALUES (?)", [("joao",), ("maria",)])

entrada = "joao' OR 1=1 --"
consulta_insegura = f"SELECT * FROM usuarios WHERE login = '{entrada}'"
print("SQL inseguro:", consulta_insegura)
print("Resultado inseguro:", cur.execute(consulta_insegura).fetchall())

resultado_seguro = cur.execute("SELECT * FROM usuarios WHERE login = ?", (entrada,)).fetchall()
print("Resultado seguro:", resultado_seguro)`} />

Saída esperada:

```text
SQL inseguro: SELECT * FROM usuarios WHERE login = 'joao' OR 1=1 --'
Resultado inseguro: [('joao',), ('maria',)]
Resultado seguro: []
```

Esse exemplo mostra por que concatenar strings em SQL é perigoso. O padrão seguro é sempre usar parâmetros em vez de montar a query diretamente com texto do usuário.

O próximo passo natural é trabalhar com várias tabelas. O `JOIN` permite combinar dados de duas tabelas relacionadas em uma mesma consulta. Isso é a base para sistemas que guardam clientes em uma tabela e pedidos em outra, e precisam cruzar essas informações.

## No mercado de trabalho

O SQLite aparece em apps de desktop, ferramentas internas, protótipos, scripts de automação e pequenos backends. Ele também é muito usado para cache local, histórico, armazenamento de configurações e dados de uso. Em outras palavras, ele resolve muita coisa sem exigir infraestrutura pesada.

Isso não é “ferramenta simples demais”. Em projetos reais, persistência é a base de qualquer sistema que precisa lembrar dados entre execuções. Quem domina banco local, SQL básico e segurança em queries tem uma base muito forte para evoluir para Flask, Django e aplicações maiores.
