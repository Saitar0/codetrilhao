# Funções avançadas

Depois que a função básica já faz sentido, a próxima etapa é entender como ela pode lidar com entradas imprevisíveis e lógica mais elegante. Em muitos programas, você não sabe ao certo quantos valores vão entrar: pode ser uma lista de notas, uma sequência de filtros ou uma série de parâmetros extras vindos de um sistema externo. É aí que entram `*args`, `**kwargs`, lambdas e recursão.

Esses recursos fazem o código ficar mais expressivo, mas também exigem calma. A ideia não é usar tudo em excesso; é usar a ferramenta certa para a situação certa. Quando você domina esses padrões, consegue escrever funções mais genéricas e mais fáceis de reutilizar.

## 1. `*args`: quantidade variável de argumentos

O símbolo `*` antes do nome do parâmetro significa: “aceite qualquer quantidade de argumentos posicionais”. Isso é útil quando você não sabe quantos números, textos ou itens serão passados.

<CodeBlock title="args.py" code={`def media(*numeros):
    if not numeros:
        return 0
    return sum(numeros) / len(numeros)

print(media(2, 4, 6))
print(media(10, 20, 30, 40))
print(media())`} />

O `*numeros` coleta os valores em uma tupla. Isso é muito útil para ferramentas de agregação, como calcular média, somar preços, validar listas e receber entradas de tamanhos variáveis. O código fica mais flexível sem ter que criar uma lista fixa de parâmetros.

Você pode até misturar parâmetros normais com `*args`, mas é importante manter a ordem: primeiro os parâmetros fixos, depois `*args`. Em uma função bem projetada, isso deixa claro quais dados são obrigatórios e quais são opcionais ou dinâmicos.

## 2. `**kwargs`: argumentos nomeados variáveis

Agora imagine uma função que recebe dados em formato de chave e valor, como configuração ou informações de um usuário. `**kwargs` coloca esses valores em um dicionário.

<CodeBlock title="kwargs.py" code={`def mostrar_configuracao(**dados):
    for chave, valor in dados.items():
        print(f"{chave}: {valor}")

mostrar_configuracao(usuario="Lia", tema="escuro", idioma="pt-BR")`} />

Esse padrão aparece muito em frameworks, funções de configuração e APIs. Você pode receber dados sem saber previamente todas as chaves. O programa persiste em um dicionário, e você pode iterar sobre esse dicionário com `.items()`.

A diferença entre `*args` e `**kwargs` é simples: `*args` recebe valores posicionais; `**kwargs` recebe pares de chave e valor. Juntos, eles formam uma combinação muito poderosa para funções genéricas.

## 3. `lambda`: funções curtas e pontuais

A palavra-chave `lambda` cria uma função anônima, ou seja, uma função sem nome oficial. Ela é útil quando a lógica é simples e não precisa ser reutilizada fora de um lugar específico.

<CodeBlock title="lambda.py" code={`dobro = lambda x: x * 2
print(dobro(7))
print((lambda x: x ** 2)(5))
print(list(map(lambda n: n + 1, [1, 2, 3, 4])))`} />

O primeiro exemplo atribui a função anônima a uma variável, então ela passa a ter um nome prático. No segundo caso, a função é usada de forma imediata. Em `map`, `lambda` transforma cada valor da lista sem que você precise escrever uma função separada. Isso torna o código mais enxuto, mas também exige cuidado: se a lógica ficar longa, uma `def` costuma ser mais legível.

<Playground title="Experimente com lambda e ordenação" code={`alunos = [
    {"nome": "Ana", "nota": 8},
    {"nome": "Beto", "nota": 9},
    {"nome": "Cida", "nota": 7},
]

ordem = sorted(alunos, key=lambda aluno: aluno["nota"], reverse=True)
print([a["nome"] for a in ordem])`} />

## 4. Recursão básica

Recursão é quando uma função chama ela mesma. Isso é útil para problemas que têm uma estrutura repetitiva, como fatorial, busca em árvore, combinações e alguns algoritmos matemáticos. A ideia é quebrar o problema em um caso menor até chegar em um caso base.

<CodeBlock title="recursao.py" code={`def fatorial(n):
    if n == 0 or n == 1:
        return 1
    return n * fatorial(n - 1)

print(fatorial(5))
print(fatorial(1))`} />

A chamada `fatorial(5)` vira `5 * fatorial(4)`, depois `4 * fatorial(3)` e assim por diante, até chegar ao caso base `1`. Esse tipo de solução pode ser elegante, mas cuidado: se você esquecer do caso base, a função entra em loop infinito e Python termina com `RecursionError`.

<StepThrough>
  <div>
    <strong>Passo 1:</strong> a função recebe <code>n = 5</code>. Como não é 0 nem 1, ela calcula <code>5 * fatorial(4)</code>.
  </div>
  <div>
    <strong>Passo 2:</strong> agora <code>n = 4</code>; ela calcula <code>4 * fatorial(3)</code>.
  </div>
  <div>
    <strong>Passo 3:</strong> esse processo continua até <code>n = 1</code>, quando a função retorna 1 e cada nível resolve a multiplicação anterior.
  </div>
</StepThrough>

Recursão exige disciplina mental. Ela é muito boa para problemas recursivos, mas para loops simples, uma estrutura `for` ou `while` costuma ser mais clara. Em outras palavras: recursão é uma ferramenta, não uma obrigação.

## 5. Armadilha do default mutável

Este ponto merece atenção. Quando você cria uma função com uma lista como valor padrão, ela é criada uma vez só, quando a função é definida. Isso significa que o estado da lista pode “acumular” itens entre chamadas.

<CodeBlock title="default_mutavel.py" code={`def registrar(item, historico=[]):
    historico.append(item)
    return historico

print(registrar("primeiro"))
print(registrar("segundo"))
print(registrar("terceiro"))`} />

A saída mostra que o histórico não reinicia a cada chamada. Isso é exatamente a armadilha: um valor padrão mutável “vive” entre as chamadas. A solução mais segura é usar `None` e criar a lista dentro da função cada vez.

<CodeBlock title="default_mutavel_corrigido.py" code={`def registrar(item, historico=None):
    if historico is None:
        historico = []
    historico.append(item)
    return historico

print(registrar("primeiro"))
print(registrar("segundo"))
print(registrar("terceiro"))`} />

Agora cada chamada começa com uma lista nova, então o comportamento é previsível. Esse detalhe aparece em programas reais quando você tem listas de filtros, histórico de operações ou registros acumulados.

<Callout type="erro-comum" title="Erro: função retorna None e você espera um valor">
  Há casos em que a função executa uma ação, mas não devolve nenhum resultado. O código compila, mas a lógica de uso fica frustrante.
  <CodeBlock title="erro_none_advanced.py" code={`def mostrar_total(numeros):
    total = sum(numeros)
    print(total)

resultado = mostrar_total([10, 20, 30])
print(resultado)`} />
  A saída real mostra `60` e depois `None`. Isso prova que a função exibiu o valor, mas não devolveu um resultado útil. A correção é ser explícito: `return total` quando o valor precisa ser reutilizado.
</Callout>

<Callout type="erro-comum" title="Erro: uso de recursão sem caso base">
  Quando a função chama a si mesma sem terminar, o problema é o caso base ausente.
  <CodeBlock title="erro_recursao.py" code={`def contar(n):
    print(n)
    return contar(n - 1)

print(contar(3))`} />
  O programa entra em recursão infinita até o Python interromper com `RecursionError`. A correção é incluir uma condição como `if n == 0: return 0` antes da chamada recursiva.
</Callout>

<Callout type="erro-comum" title="Erro: `kwargs` ou `args` usados sem pensar na estrutura">
  `*args` e `**kwargs` podem tornar a função flexível demais e quase impossível de ler se você não controlar a intenção.
  <CodeBlock title="erro_kwargs.py" code={`def mostrar(**dados):
    print(dados["nome"])

mostrar(idade=30)`} />
  A mensagem real é `KeyError: 'nome'` porque a chave `nome` não foi enviada. A correção é validar os dados e tratar ausência de chaves com `dados.get("nome", "desconhecido")` ou verificar antes de acessar.
</Callout>

### No mercado de trabalho

Funções avançadas aparecem em bibliotecas, sistemas de integração e ferramentas de data science. Quando você recebe dados em formatos heterogêneos, `*args` e `**kwargs` ajudam a escrever interfaces flexíveis. Já `lambda` aparece em filtros e ordenações simples. Recursão entra em algoritmos, busca e manipulação de estruturas hierárquicas.

A maior lição aqui não é “usar tudo que Python permite”; é entender quando cada recurso traz clareza. Em ambiente profissional, código confuso é mais perigoso do que código mais simples. A melhor função é aquela que resolve bem o problema e continua fácil de manter depois.

  <li>`**kwargs` permite receber dicionários de parâmetros nomeados.</li>
  <li>`lambda` é útil para lógicas curtas e específicas.</li>
  <li>Recursão resolve problemas menores até um caso base.</li>
