# Métodos especiais

Quando você imprime um objeto simples em Python, a saída costuma ser pouco útil: algo como `<__main__.Produto object at 0x...>`. Isso não é uma mensagem amigável para quem está lendo o código ou depurando um problema. Por isso, existem os métodos especiais, também chamados de “dunder methods”, que permitem definir como o objeto se comporta em operações comuns do Python.

Esses métodos fazem o objeto parecer “nativo” da linguagem. Em vez de ter uma saída genérica, você pode controlar o que acontece ao converter para string, comparar objetos, calcular tamanho ou acessar elementos.

  - Como `__str__` e `__repr__` controlam a exibição do objeto.
  - Como `__eq__`, `__lt__` e `__len__` definem comparação e comportamento.
  - Quando os métodos especiais deixam o código mais claro e expressivo.
  - Como evitar comparações por identidade quando o contexto pede igualdade por valor.
</Callout>

## `__str__` e `__repr__`

O método `__str__` define a representação legível de um objeto para humanos. Já `__repr__` é a representação principal para desenvolvedores, normalmente mais detalhada.

```python
class Produto:
    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco

    def __str__(self):
        return f"{self.nome} por R$ {self.preco:.2f}"

    def __repr__(self):
        return f"Produto(nome={self.nome!r}, preco={self.preco!r})"

p = Produto("Mouse", 49.9)
print(str(p))
print(repr(p))
```

Saída:

```text
Mouse por R$ 49.90
Produto(nome='Mouse', preco=49.9)
```

A diferença é de propósito: `str` foca em leitura simples; `repr` ajuda no debug. Em muitos projetos, isso torna o código muito mais fácil de acompanhar.

## `__len__`, `__getitem__` e a integração com o Python

Os métodos especiais também permitem que seus objetos se comportem como estruturas nativas. Assim, um objeto pode ter um tamanho, suportar acesso por índice e até comparações sem precisar de regras externas.

```python
class Colecao:
    def __init__(self, itens):
        self.itens = itens

    def __len__(self):
        return len(self.itens)

    def __getitem__(self, index):
        return self.itens[index]

c = Colecao([10, 20, 30])
print(len(c))
print(c[1])
```

Saída:

```text
3
20
```

Isso faz parte da “gramática” do Python: o objeto passa a se comportar como uma coleção legítima, o que melhora a ergonomia do código.

## `__eq__` e comparação por valor

Quando você compara dois objetos com `==`, o Python usa a igualdade por identidade, a menos que você defina `__eq__`. Isso significa que, por padrão, objetos diferentes com os mesmos dados ainda são considerados distintos.

```python
class Item:
    def __init__(self, nome, quantidade):
        self.nome = nome
        self.quantidade = quantidade

    def __eq__(self, other):
        if not isinstance(other, Item):
            return NotImplemented
        return self.nome == other.nome and self.quantidade == other.quantidade

a = Item("Caneta", 3)
b = Item("Caneta", 3)
print(a == b)
```

Saída:

```text
True
```

Esse tipo de método é útil em classes que representam valores: se duas instâncias representam a mesma entidade, você pode considerar them iguais, e não apenas “mesma referência de memória”.

## Métodos especiais em código real

No mundo real, os métodos especiais aparecem em classes que representam valores, estruturas de dados e domínios de negócio. Quando você modela `Pedido`, `Produto`, `Cliente` ou `Pilha`, essas operações ajudam a integrar sua classe ao comportamento natural do Python. Não é luxo: é ergonomia e clareza.

<Callout type="erro-comum" title="Comparar objetos sem __eq__">
  ```python
  class Produto:
      def __init__(self, nome):
          self.nome = nome

  p1 = Produto("Teclado")
  p2 = Produto("Teclado")
  print(p1 == p2)
  ```

  Saída real:

  ```text
  False
  ```

  Esse comportamento acontece porque Python compara identidade por padrão. A correção é implementar `__eq__` para comparar os atributos relevantes.
</Callout>

<Callout type="erro-comum" title="Esperar `str(obj)` sem definir `__str__`">

  ```python
  class Pedido:
      def __init__(self, numero):
          self.numero = numero

  print(Pedido(42))
  ```

  Saída real:

  ```text
  <__main__.Pedido object at 0x...>
  ```

  A saída depende do endereço de memória e não é útil. A solução é implementar `__str__` para uma mensagem clara e amigável.
</Callout>
