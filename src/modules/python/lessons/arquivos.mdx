# Arquivos

Imagine que você precisa guardar uma lista de tarefas, exportar o cadastro de clientes para uma planilha ou salvar o histórico de uma aplicação. Em Python, isso é um dos passos mais comuns quando o programa precisa continuar existindo além da execução atual. O arquivo transforma memória em persistência.

Você vai aprender a criar, ler, escrever e organizar dados em formatos que o mundo real usa todos os dias: texto simples, CSV e JSON. E, para ficar claro desde o começo, um detalhe importante: você não lê um arquivo que não existe. Primeiro você cria o arquivo e depois o lê.

    <li>Reconhecer erros comuns como arquivo ausente, encoding errado e sobrescrita acidental.</li>
  </ul>

<Callout type="importante" title="Arquivos vivem em memória">
  Em Python, os arquivos não “aparecem sozinhos” no programa. O fluxo de um exercício típico é: criar o arquivo, escrever os dados, fechar ou liberar o recurso e só então ler o conteúdo de volta. Se você tentar ler primeiro, o Python geralmente lança <strong>FileNotFoundError</strong> porque o arquivo ainda não existe no ambiente de execução.

  Isso não é um erro de Python — é uma regra do fluxo real de persistência. Em todos os exercícios do tópico, você vai criar o arquivo antes de lê-lo. Essa ideia vale tanto para um `.txt` simples quanto para um `.csv` ou um `.json`.
</Callout>

<Callout type="dica" title="Dica prática: os dados de exemplo entram como string">
  Quando você está escrevendo exemplos de aula, os dados que entram no arquivo geralmente ficam em texto. Em outras palavras, você escreve uma string: <code>"Ana\nBia\n"</code>, não uma lista ou um dicionário bruto diretamente como se fosse a saída final. Depois, você lê e transforma esse texto em estrutura de dados quando necessário.
</Callout>

## 1. Abrindo um arquivo: `open`, `with` e modos

A função `open()` é a porta de entrada para qualquer arquivo em Python. Você indica o nome do arquivo, o modo de acesso e, em muitos casos, o `encoding`. Os modos mais usados são `'r'` para ler, `'w'` para escrever e sobrescrever, `'a'` para acrescentar ao final e `'x'` para criar um arquivo novo e falhar se ele já existir.

O bloco `with` é quase sempre o melhor jeito de abrir arquivos, porque ele garante que o arquivo será fechado no fim do bloco, mesmo que aconteça algum erro. Em Python, fechar arquivos é importante porque o seu programa pode manter o recurso aberto por mais tempo do que o necessário, e isso vira um problema real em aplicações maiores.

<CodeBlock title="escrever_e_ler_txt.py" code={`with open("lista.txt", "w", encoding="utf-8") as arquivo:
    arquivo.write("Python\n")
    arquivo.write("CSV\n")
    arquivo.write("JSON\n")

with open("lista.txt", "r", encoding="utf-8") as arquivo:
    print(arquivo.read())`} />

Saída esperada:

```text
Python
CSV
JSON
```

Você acabou de criar um arquivo em texto simples, escrever três linhas e lê-lo de volta. Esse padrão é o “hello world” da persistência: escrever, fechar e ler. A forma mais didática de pensar nisso é: o arquivo está em disco, mas o Python também trabalha com ele em memória durante a operação.

## 2. Ler, ler linha por linha e contar linhas

Quando você precisa processar textos longos, costuma não ler tudo de uma vez. Em vez disso, você pode usar `read()`, `readline()` ou `readlines()`, e também percorre o arquivo linha por linha com `for linha in arquivo`.

Essa diferença importa porque cada abordagem serve a uma necessidade. `read()` devolve tudo em uma string única; `readline()` devolve uma linha de cada vez; `readlines()` devolve uma lista com todas as linhas. A linha por linha é especialmente útil quando você quer contar itens, validar cada entrada ou transformar cada registro à medida que lê.

<CodeBlock title="ler_linhas.py" code={`with open("notas.txt", "w", encoding="utf-8") as arquivo:
    arquivo.write("8\n")
    arquivo.write("9\n")
    arquivo.write("10\n")

with open("notas.txt", "r", encoding="utf-8") as arquivo:
    linhas = arquivo.readlines()
    print(linhas)
    print("Quantidade de linhas:", len(linhas))

with open("notas.txt", "r", encoding="utf-8") as arquivo:
    for linha in arquivo:
        print(f"Linha lida: {linha.strip()}")`} />

Saída esperada:

```text
['8\n', '9\n', '10\n']
Quantidade de linhas: 3
Linha lida: 8
Linha lida: 9
Linha lida: 10
```

Quando você percorre um arquivo em looping, cada linha vem com uma quebra de linha `\n` ao final. Por isso, a prática comum é usar `strip()` para remover espaços e quebras extras quando você quer limpar o valor antes de processar. Isso é muito útil para validar dados, fazer contagem ou preparar listas de strings.

## 3. `pathlib.Path`: caminhos, existência e pastas

O módulo `pathlib` facilita o trabalho com caminhos de arquivos e diretórios. Em vez de montar strings em vez de montar caminhos manualmente, você usa `Path("nome_do_arquivo.txt")`, `Path("dados") / "arquivo.txt"` e verifica com `.exists()` se o caminho realmente existe.

Isso é muito importante quando você trabalha em projetos mais organizados. Você pode ter pastas de entrada, saída e logs; cada uma delas precisa ser acessada com clareza. A criação de diretórios também é simples com `mkdir(parents=True, exist_ok=True)`.

<CodeBlock title="pathlib_e_pastas.py" code={`from pathlib import Path

caminho = Path("dados") / "contatos.txt"
caminho.parent.mkdir(parents=True, exist_ok=True)

caminho.write_text("Ana\nBia\nCarlos\n", encoding="utf-8")
print("Existe?", caminho.exists())
print(caminho.read_text(encoding="utf-8"))`} />

Saída esperada:

```text
Existe? True
Ana
Bia
Carlos
```

Você vê aqui a vantagem do `Path`: o código fica mais legível e menos frágil. Se o arquivo estiver dentro de uma pasta, você não precisa “adivinhar” o caminho exato e, ao mesmo tempo, a validação com `.exists()` deixa explícita a intenção do programa.

## 4. CSV: planilhas em texto

CSV significa “Comma-Separated Values”, mas em Python você vai encontrá-lo muito além de vírgula: também pode ser usado com `;`, conforme a região e o padrão do dado. O formato funciona muito bem para tabelas simples, como lista de clientes, produtos ou vendas.

A vantagem do CSV é que ele é legível por humanos e por Excel, e ainda assim é fácil de ler em Python com o módulo `csv`. Existem duas formas comuns: `csv.reader` para ler como lista e `csv.DictReader` para ler como dicionários, onde a primeira linha serve como cabeçalho.

<CodeBlock title="csv_reader.py" code={`import csv

with open("produtos.csv", "w", encoding="utf-8", newline="") as arquivo:
    escritor = csv.writer(arquivo, delimiter=';')
    escritor.writerow(["nome", "preco", "estoque"])
    escritor.writerow(["Livro", "39.90", "12"])
    escritor.writerow(["Caneta", "7.50", "90"])

with open("produtos.csv", "r", encoding="utf-8", newline="") as arquivo:
    leitor = csv.reader(arquivo, delimiter=';')
    for linha in leitor:
        print(linha)`} />

Saída esperada:

```text
['nome', 'preco', 'estoque']
['Livro', '39.90', '12']
['Caneta', '7.50', '90']
```

O `csv.writer` criou uma tabela em texto e o `csv.reader` conseguiu lê-la de volta. Se você quiser estruturas mais semânticas, o `DictReader` vira a linha em um dicionário com as chaves do cabeçalho. Isso é muito útil quando você precisa trabalhar com dados “em formato de registro”.

<CodeBlock title="csv_dictreader.py" code={`import csv

with open("alunos.csv", "w", encoding="utf-8", newline="") as arquivo:
    campos = ["nome", "idade", "curso"]
    escritor = csv.DictWriter(arquivo, fieldnames=campos, delimiter=';')
    escritor.writeheader()
    escritor.writerow({"nome": "Ana", "idade": "30", "curso": "Python"})
    escritor.writerow({"nome": "Bia", "idade": "22", "curso": "SQL"})

with open("alunos.csv", "r", encoding="utf-8", newline="") as arquivo:
    leitor = csv.DictReader(arquivo, delimiter=';')
    for linha in leitor:
        print(linha)`} />

Saída esperada:

```text
{'nome': 'Ana', 'idade': '30', 'curso': 'Python'}
{'nome': 'Bia', 'idade': '22', 'curso': 'SQL'}
```

Atenção: o `csv` lê tudo como string. Isso é muito comum. Nome e curso vêm como texto, e o valor da idade também. Se você quiser tratá-lo como número, precisará converter com `int()` ou `float()` depois da leitura. Em outras palavras, CSV é excelente para tabular, mas nem sempre é o formato mais natural para cálculos ao mesmo tempo.

## 5. JSON: estruturas de dados em texto

JSON é o formato mais usado para trocar informações entre programas, APIs e serviços. Ele representa dados em estruturas familiares do Python: dicionários e listas. Em vez de escrever uma tabela plana, você grava uma estrutura com chaves e valores. Isso funciona muito bem para representar objetos complexos, como clientes, pedidos, configurações e respostas de API.

Em Python, o módulo `json` oferece `json.dumps()` para transformar dados em texto e `json.loads()` para transformar texto em dados. Se você quiser gravar um arquivo com o conteúdo em disco, use `json.dump()` e `json.load()` com o arquivo aberto em modo de escrita ou leitura.

<CodeBlock title="json_dumps_e_loads.py" code={`import json

dados = [
    {"tarefa": "estudar", "feito": False},
    {"tarefa": "praticar", "feito": True},
]

texto = json.dumps(dados, ensure_ascii=False, indent=2)
print(texto)

lista = json.loads(texto)
print(lista[0]["tarefa"])`} />

Saída esperada:

```text
[
  {
    "tarefa": "estudar",
    "feito": false
  },
  {
    "tarefa": "praticar",
    "feito": true
  }
]
estudar
```

Observe que o `json.dumps()` converte os dados em uma string textual, e `json.loads()` faz o processo inverso. Isso é exatamente o que você precisa ao salvar estruturas mais ricas em arquivo. Em APIs do mundo real, JSON é a forma que melhor representa “objetos com propriedades”, e isso explica por que ele aparece tão cedo na rotina de qualquer desenvolvedor.

<CodeBlock title="json_em_arquivo.py" code={`import json
from pathlib import Path

caminho = Path("dados.json")
dados = [{"nome": "Ana", "notas": [8, 9.5], "ativo": True}]

with caminho.open("w", encoding="utf-8") as arquivo:
    json.dump(dados, arquivo, ensure_ascii=False, indent=2)

with caminho.open("r", encoding="utf-8") as arquivo:
    leitura = json.load(arquivo)
    print(leitura)
    print(leitura[0]["nome"])`} />

Saída esperada:

```text
[{'nome': 'Ana', 'notas': [8, 9.5], 'ativo': True}]
Ana
```

## 6. Quando usar txt, CSV ou JSON?

Nem todo formato serve para o mesmo fim. A escolha certa depende do tipo de dado e do objetivo do programa. O texto simples é fácil de escrever e ler, mas não representa estrutura de tabela; o CSV é ótimo para listas de registros; o JSON é excelente para objetos aninhados e troca de dados entre sistemas.

<Tabela data={[
  ['Formato', 'Melhor para', 'Exemplo', 'Observação'],
  ['txt', 'anotações, logs e textos simples', 'lista de tarefas em linhas', 'é fácil de ler, mas sem estrutura formal'],
  ['CSV', 'tabelas e registros tabulares', 'nome;idade;cidade', 'bom para Excel e relatórios simples'],
  ['JSON', 'dados estruturados e aninhados', '{"nome": "Ana", "idade": 30}', 'melhor para APIs, configurações e objetos complexos']
]} />

Você pode usar o mesmo dado em formatos diferentes, dependendo do contexto. Um cadastro de clientes pode ser salvo em CSV para revisão em planilha; o mesmo cadastro também pode ser enviado como JSON para um sistema web. A habilidade real não é “aprender um formato” isoladamente, e sim decidir qual é o melhor para a tarefa, mantendo a leitura e a escrita consistentes.

## 7. Erros comuns e como evitar

Os erros de arquivos aparecem em todas as fases do desenvolvimento. Às vezes, o problema é só um caminho errado; outras vezes, você sobrescreve dados sem querer. O importante é reconhecer o padrão e não deixar o programa “quebrar no limbo”.

<Callout type="erro-comum" title="FileNotFoundError">
  <CodeBlock title="arquivo_inexistente.py" code={`from pathlib import Path

conteudo = Path("dados/estoque.txt").read_text(encoding="utf-8")
print(conteudo)`} />
  <p>Erro real: <strong>FileNotFoundError: [Errno 2] No such file or directory: 'dados/estoque.txt'</strong></p>
  <p>Correção: verifique se o caminho existe com <code>.exists()</code>, crie a pasta com <code>mkdir()</code> e só então leia o arquivo.</p>
</Callout>

<Callout type="erro-comum" title="Acentos quebrados">
  <CodeBlock title="encoding_errado.py" code={`texto = "café e coração"

with open("acentos.txt", "w", encoding="utf-8") as arquivo:
    arquivo.write(texto)

with open("acentos.txt", "r", encoding="cp1252") as arquivo:
    print(arquivo.read())`} />
  <p>Saída real: <strong>cafÃ© e coraÃ§Ã£o</strong> ou uma sequência parecida, dependendo do ambiente de leitura.</p>
  <p>Correção: use a mesma codificação em escrita e leitura, normalmente <code>encoding="utf-8"</code>.</p>
</Callout>

<Callout type="erro-comum" title="Dados apagados por sobrescrita">
  <CodeBlock title="sobrescrever_arquivo.py" code={`with open("contatos.txt", "w", encoding="utf-8") as arquivo:
    arquivo.write("Ana\n")

with open("contatos.txt", "w", encoding="utf-8") as arquivo:
    arquivo.write("Bia\n")

with open("contatos.txt", "r", encoding="utf-8") as arquivo:
    print(arquivo.read())`} />
  <p>Saída real: <strong>Bia</strong></p>
  <p>Correção: use <code>'a'</code> para acrescentar ou leia o conteúdo antes de escrever, para não perder registros antigos.</p>
</Callout>

Esses três erros aparecem com muita frequência e valem a pena memorizar. Em programação real, o diagnóstico quase sempre é simples: “o caminho está errado”, “a codificação está inconsistente” ou “o modo de abertura sobrescreveu o conteúdo”. A boa notícia é que todas essas correções são pequenas, mas fazem uma diferença enorme na qualidade do programa.

## No mercado de trabalho

No mercado, arquivos aparecem em praticamente todo sistema que precisa de persistência. Um back-end pode salvar histórico de pedidos em JSON, um analista pode exportar uma base em CSV para a área financeira e uma ferramenta interna pode escrever logs em TXT para ajudar na operação. O que muda é o formato, não a ideia central: você precisa gravar dados de forma confiável e lê-los depois sem perder a estrutura.

Em profissões como desenvolvimento de software, automação, ciência de dados e análise de negócios, essa rotina é frequentemente usada para criar reports, gerar dados de entrada, limpar planilhas e integrar sistemas. Saber escolher entre TXT, CSV e JSON mostra que você entende tanto a sintaxe quanto a intenção da aplicação. Em outras palavras, você deixa de “escrever uma linha em arquivo” e passa a “salvar dados de forma correta para um cenário real”.

## 8. Resumo prático

A lógica central do tópico é simples, mas poderosa:

- `open()` abre um arquivo em modo específico.
- `with` garante que tudo seja fechado corretamente.
- `txt` é bom para texto simples.
- `CSV` é bom para tabelas e listas de registros.
- `JSON` é bom para estruturas aninhadas, como dicionários e listas de dicionários.
- `encoding="utf-8"` evita problemas com acentos e caracteres internacionais.
- `w` sobrescreve; `a` acrescenta; `r` lê.

Quando você entende isso, a manipulação de arquivos deixa de parecer mágica e vira uma rotina clara de leitura, escrita e validação.
