# Finanças pessoais

## Contexto
Você foi contratado para montar um painel simples para uma pessoa que quer tomar controle da vida financeira sem depender de planilhas complexas. A meta não é criar um sistema enorme; é construir um lugar confiável para registrar receitas, despesas, categorias e metas de economia. Com o tempo, esse programa pode virar um assistente pessoal para decisões de orçamento.

## O que você vai construir
Um gerenciador de finanças pessoais em terminal. O sistema permite registrar movimentações, classificar gastos, calcular saldo, listar a última movimentação por categoria e gerar um relatório mensal. A ideia é manter a lógica principal separada em classes, funções e persistência em SQLite.

## Requisitos
1. Menu interativo em loop com opções para adicionar movimentação, listar, filtrar e sair.
2. Classes para `Transacao`, `Categoria` e `Carteira` ou `ControleFinanceiro`.
3. Persistência em SQLite com tabelas para `categorias` e `transacoes`.
4. Validação de entradas como valor positivo, data válida e categoria obrigatória.
5. Cálculo de saldo atual e de saldo por mês.
6. Relatório textual ou CSV com receitas, despesas e total final.
7. Tratamento de erros para arquivo, banco e valores inválidos.
8. Funções separadas para cadastrar, listar, filtrar e exportar relatório.
9. README com instruções de uso e exemplo de execução.
10. Testes automatizados cobrindo regras de negócio principais.

## Critérios de aceite
- [ ] O programa consegue registrar receitas e despesas em uma mesma execução.
- [ ] O usuário consegue visualizar saldo atual e por categoria.
- [ ] O sistema salva os dados em SQLite e lê a base corretamente.
- [ ] Valores negativos ou vazios são rejeitados com mensagem clara.
- [ ] O relatório mensal mostra lucro, gasto total e saldo final.
- [ ] O código está organizado em módulos e funções com nomes significativos.
- [ ] Há testes cobrindo entradas válidas e inválidas.

## Histórias de usuário
1. Como usuário, quero registrar uma receita para manter o controle do saldo.
2. Como usuário, quero separar despesas por categoria para entender onde o dinheiro está indo.
3. Como usuário, quero ver um relatório do mês para avaliar se estou economizando.
4. Como usuário, quero receber uma mensagem clara quando o valor ou a data estiverem inválidos.

## Modelo de dados
Use classes e tabelas SQLite para separar domínio e persistência.

```python
from dataclasses import dataclass
from datetime import date

@dataclass
class Transacao:
    descricao: str
    valor: float
    categoria: str
    tipo: str
    data: date
```

```sql
CREATE TABLE IF NOT EXISTS categorias (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nome TEXT NOT NULL UNIQUE
);

CREATE TABLE IF NOT EXISTS transacoes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    descricao TEXT NOT NULL,
    valor REAL NOT NULL,
    tipo TEXT NOT NULL CHECK(tipo IN ('receita', 'despesa')),
    categoria_id INTEGER NOT NULL,
    data TEXT NOT NULL,
    FOREIGN KEY (categoria_id) REFERENCES categorias(id)
);
```

## Guia
### Como começar
- Defina as categorias principais: alimentação, transporte, moradia, saúde e lazer.
- Crie a interface de menu com funções pequenas e um módulo para banco de dados.
- O saldo deve ser calculado a partir das transações e não armazenado manualmente.

### Tratamento de erros
- Se o valor não for numérico, diga `Valor inválido.`
- Se a categoria não existir, ofereça a opção de criá-la.
- Se a data estiver vazia ou fora do formato, rejeite a entrada.

### Dicas práticas
- Use `sqlite3.Row` para facilitar a leitura das colunas.
- Prefira `SELECT` com filtros por mês e categoria em vez de carregar tudo.
- Faça uma regra de negócio central para “receita aumenta o saldo; despesa reduz”.

## Desafio extra
Adicione uma função de `resumo_do_mes` que mostre percentual gasto em cada categoria e destaque a maior despesa do período.
